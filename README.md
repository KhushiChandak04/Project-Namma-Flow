# Namma Flow

Namma Flow is a software-only Progressive Web App concept for Bangalore that helps distribute urban travel load instead of only reporting congestion.

## Product

- **The Grid:** commuter planning from origin and destination to a demo multi-modal route, congestion-aware departure recommendation, and duration.
- **The Compass:** explorer search such as `cozy cafe`, `quiet park`, or `live music`, ranked toward lower-congestion demo zones.

All traffic values, destinations, routes, discounts, and schedules in the MVP are simulated. The app does not claim live BMTC, metro, traffic, payment, ticketing, dispatch, or authentication integrations.

## Repository layout

```text
frontend/                 React/Vite/Tailwind application
  src/components/         Shared shell and feature UI boundaries
  src/pages/              Grid and Compass pages
  src/data/                Demo zones, routes, and vibes
  src/services/            API, trip, and vibe adapters
  src/utils/               Shared deterministic helpers
experiments/backend-aws/  Archived AWS/Lambda experiments, not used
docs/                     Architecture and team contracts
scripts/                  Repository smoke tests
```

The frontend includes Leaflet map surfaces in `frontend/src/components/maps/`. `frontend/src/data/mockResponses.js` contains deterministic, clearly simulated contracts for the three demo journeys. See [docs/TECH_STACK.md](docs/TECH_STACK.md) for implemented versus planned technologies.

## Local setup

Requirements: Node.js and npm.

```bash
copy .env.example frontend\.env.local
npm install
npm run dev
```

For PowerShell, `Copy-Item .env.example frontend\.env.local` is equivalent to `copy`.

Run those commands from the repository root. The root `package.json` is the team entry point and delegates commands to `frontend/`. Do not start Vite with a path-prefixed npm command; use the root script so Vite receives the frontend workspace as its working directory.

The direct frontend equivalent is:

```bash
cd frontend
npm install
npm run dev
```

### Deploy to Vercel

In Vercel, import the repository and set the project root directory to `frontend`. [frontend/vercel.json](./frontend/vercel.json) installs from the frontend lockfile, builds with `npm run build`, publishes `dist`, and rewrites client-side routes to `index.html`.

Frontend environment variables are browser-visible and must contain only public `VITE_*` values:

```env
VITE_API_BASE_URL=
VITE_USE_MOCK_API=true
VITE_SUPABASE_URL=
VITE_SUPABASE_ANON_KEY=
```

Trip planning runs entirely in the frontend using deterministic demo data. `VITE_USE_MOCK_API=true` remains for compatibility with the Compass service.

### Optional Supabase congestion reports

Crowd reports are optional. If the two Supabase variables are blank, the app uses the simulated time-of-day baseline and does not write anything. To enable reports, create this table and its policies in the Supabase SQL Editor:

```sql
create table public.congestion_reports (
  id bigint generated by default as identity primary key,
  zone_id text not null,
  hour smallint not null check (hour between 0 and 23),
  rating smallint not null check (rating between 1 and 5),
  created_at timestamptz not null default now()
);

alter table public.congestion_reports enable row level security;

create policy "Anyone can read congestion reports"
  on public.congestion_reports for select
  to anon
  using (true);

create policy "Anyone can submit congestion reports"
  on public.congestion_reports for insert
  to anon
  with check (true);
```

Then copy the project URL and the public anon key from Supabase **Project Settings → API** into `frontend/.env.local`:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-public-anon-key
```

The frontend only reads reports from the last 90 days and caches each zone/hour read in memory for 10 minutes. Because this demo has no user authentication, the anonymous insert policy allows public submissions; add authentication, rate limiting, or an Edge Function before treating the reports as trusted production data.

## Verification

From the repository root:

```bash
npm run smoke
npm run build
```

The smoke test imports the shared data/helpers and verifies the demo journeys' core contracts. The production build outputs to `frontend/dist`.

## Known limitations

- There is no live traffic feed; congestion uses a time-of-day baseline and optional crowd reports.
- Bus timings are not live.
- Public feedback submissions are open to abuse because this demo has no user authentication or rate limiting.
- The public OSRM server is intended for light use only.
- OpenStreetMap/Overpass availability can vary; the app falls back to its route catalog when transit lookup fails.

If the browser is blank, confirm the terminal says `Local: http://localhost:5173/`, open that exact URL, and restart with `npm run dev` from the repository root. A Vite process started from the wrong directory can serve a 404 instead of the app.

## Architecture

The project is a static frontend with no AWS services in use. Backend code is parked in `experiments/backend-aws/` and is not live or deployed. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
